# Проверка версии 0.4.0

Среда: macOS ARM64, официальный .NET SDK 10.0.404, Windows runtime 10.0.15,
PowerShell 7.7.0. Цель: Windows x64. TreatWarningsAsErrors включён.

## Выполнено

- 224 проверки C#: протокол, подбор, обновления, состояния интерфейса, установка,
  формат иконки, диагностика запуска, Game Filter и Telegram.
  Использованы локальный WebSocket-сервер, официальный ZIP
  Flowseal 1.10.4 и все его 22 стратегии.
- Все 22 стратегии разбираются с выключенным Game Filter и в режимах All/Tcp/Udp.
  Проверены отдельные диапазоны, legacy-переменная, исключения, сохранение настроек,
  старый JSON без Game Filter, недопустимые порты и CIDR.
- Выполнена настоящая загрузка IPSet Flowseal и проверка сетей. Проверены свежий
  кэш, сетевой сбой, HTML вместо списка, отмена и отсутствие пригодного кэша.
- Вертикальное окно 440 × 680 с фиксированным размером, название «Связь».
  Папка ProgramFiles/DiscordRoute/Data, задача и mutex сохраняют прежние имена.
- Основная кнопка подключает, отменяет или отключает по текущему состоянию.
- Иконка встроена в EXE и WPF-ресурсы в размерах 16/24/32/48/64/128/256.
  Та же иконка используется окном и треем; проверены ICO и PE-ресурсы сборки.
- Состояние интерфейса: работающий процесс не равен успешной проверке; занятость
  блокирует изменение параметров; голос может провалиться отдельно; отмена
  очищает ожидание; команды игнорируют вызов в запрещённом состоянии.
- Установка для автозапуска: EXE и пять DLL копируются целиком; неизменённая
  версия используется повторно; новая ставится отдельно; неполный исходник и
  повреждённая установленная копия отклоняются. Предыдущая версия сохраняется.
- Протокол: валидный Hello, неверный opcode, границы размера, фрагментированные
  реальные WebSocket-ответы и отмена ожидания на локальном сервере.
- Защита загрузки: SHA-256, ZIP traversal, symlinks, имена Windows, коллизии регистра,
  строгий парсер стратегий, сохранение пользовательских списков и настроек.
- Автоподбор: приоритет сохранённой стратегии, обязательный голос, две полные
  проверки, остановка при отмене/неудаче. Обновления: продвижение нового пакета,
  откат и восстановление прежнего процесса при ошибке записи настроек.
- 11 PowerShell-проверок: синтаксис, порядок sign/verify, SHA-256 и timestamp,
  отказ при ошибке подписи/проверки, недоверии, отсутствии timestamp, другом
  сертификате, неполных параметрах и отсутствии EXE. SignTool и Authenticode
  заменены тестовыми функциями: настоящей подписи эти проверки не создают.
- Сборка XAML и публикация self-contained Windows x64 без предупреждений и ошибок.
  Нативная самораспаковка отключена; пять WPF DLL поставляются рядом с EXE.
- Независимое ревью: проверены привязки, ресурсы Fluent, подпись и установка;
  исправлена повторная инициализация при повторном WPF Loaded.
- Полный unsigned-путь build.ps1 выполнен через PowerShell на macOS; архив и
  SHA-256 проверены. Подпись реальным сертификатом не выполнялась.

Реальная загрузка GitHub ранее проверена в версии 0.1.0 (68 проверок с сетевым
smoke-test). Код загрузки релизных ZIP в 0.4.0 не менялся; этот сетевой тест не
повторялся. Новый путь загрузки текстового IPSet проверен отдельным сетевым тестом.

## Не выполнено — требуется проверка на пользовательском Windows-компьютере

В 0.2.1 пользователь сообщил об ошибке TypeConverterMarkupExtension на Windows 11.
Обнаружено несоответствие ICO: PNG-кадры RGB24 при заголовках 32bpp. Новый тест
упал на старом файле и прошёл после преобразования всех кадров в RGBA32. RGB-пиксели
сохранены точно. Это вероятная причина исходного сбоя. В 0.4.0 создание окна, декодирование ICO
через WPF и создание иконки трея уже прошли проверку на Windows CI; воспроизведение
на конкретном Windows 11 пользователя пока не выполнялось.
Требование формата: https://devblogs.microsoft.com/oldnewthing/20101022-00/?p=12473

- Визуальный запуск WPF, светлая/тёмная/контрастная тема, масштабы 100/150/200%,
  клавиатурная навигация, Narrator, поведение трея и меню.
- Реальная работа WinDivert и стратегий в сети пользователя.
- Фильтрация TCP/UDP в конкретных играх; сохранение настроек через WPF и применение
  на новом подключении. Сохранение должно быть недоступно при работающем winws.
- Определение актуального сервера из журналов Discord и ответ настоящего голосового
  сервера без входа в аккаунт из приложения. Передача звука вообще не измеряется.
- Создание/обновление задачи Планировщика, вход в Windows и отключение автозапуска.
- Job Object: завершение winws при выходе/аварии, отсутствие сирот.
- Подпись доверенным сертификатом, проверка цепочки доверия на Windows и SmartScreen.

## Windows smoke test

1. Выйти из предыдущей версии через трей. Распаковать весь ZIP, включая пять DLL.
2. Запустить Связь.exe от учётной записи администратора. Проверить скачивание пакета
   и задачу DiscordRoute-<SID>, указывающую в Program Files/DiscordRoute/Versions.
3. Проверить вкладки, Tab-навигацию, масштаб и тему, иконку в Проводнике и трее.
   Окно не должно растягиваться или разворачиваться. Сменить тему после отключения:
   приложение не должно подключаться заново из-за повторного Loaded.
4. Остановить другую установку zapret, открыть Discord и нажать подключение.
   Если нужен адрес — попробовать войти в голосовой канал. Подтверждение звука не нужно.
5. Успех допустим после двух проверок всех трёх служб. Проверить один управляемый winws.
6. Отменить подбор: процесс должен остановиться. Повторно подключиться.
7. Крестик оставляет приложение в трее. Выход через трей завершает winws и Telegram-прокси.
8. Выйти/войти в Windows: приложение запускается в трее и подбирает стратегию.
9. Выключить автозапуск и повторить вход: приложение не запускается.

Успешная компиляция и автоматические проверки не заменяют эти проверки Windows.

Для Telegram: запустить прокси → открыть ссылку в Telegram Desktop → подтвердить,
проверить сообщения и звонки. Остановить прокси, сменить порт и сохранить параметры,
снова открыть ссылку. Проверить запуск вместе со «Связью» после входа в Windows.
Ответ локального TCP-порта не считается проверкой работы Telegram в сети.
