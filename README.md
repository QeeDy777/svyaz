# Связь — Windows x64

[Сайт](https://qeedy777.github.io/svyaz/) ·
[Скачать для Windows](https://github.com/QeeDy777/svyaz/releases/latest) ·
[Сообщить об ошибке](https://github.com/QeeDy777/svyaz/issues)

Приложение подбирает стратегию Flowseal zapret для Discord, оставляет прошедшую
проверки работать, обновляет официальный пакет с GitHub и запускается при входе
в Windows. Версия 0.11.1 автоматически выполняет полный подбор при первом подключении.
Автообновление самой «Связи» сохраняет настройки.
Вертикальное окно 440 × 680 сохраняет фиксированный размер и одну кнопку подключения.
Требуется проверка на Windows-компьютере.

В 0.2.2 исправлен неверный формат иконки, способный вызывать ошибку
`TypeConverterMarkupExtension` при открытии окна. Если запуск всё же завершится
ошибкой, диалог покажет вложенную причину и путь к `startup-error.log`.

## Запуск

1. Запустите `Svyaz-0.11.1-win-x64-setup-unsigned.exe` и пройдите установку.
   Приложение появится в меню «Пуск»; ярлык на рабочем столе — по желанию.
   Распаковывать файлы и отдельно устанавливать .NET не нужно.
2. Подтвердите запрос прав администратора. Они нужны для WinDivert и автозапуска.
3. При первом запуске приложение скачает официальный пакет Flowseal с GitHub.
4. Нажмите круглую кнопку **«Подключить»**. Последняя успешная стратегия проверяется
   первой; остальные запускаются по очереди. Успех требует двух полных проверок.
5. Эта же кнопка отменяет подбор во время проверки и отключает работающий обход.
   Крестик сворачивает приложение в трей.
   Полный выход — правый клик по значку в трее → **«Выход (остановить всё)»**.

.NET устанавливать отдельно не нужно. Приложение рассчитано на Windows 10/11 x64
и учётную запись с правами администратора. Если уже работает другой zapret,
сначала остановите его штатным способом. DiscordRoute не завершает чужие процессы.

«Связь» — новое имя DiscordRoute. Папка данных и имя задачи сохраняют прежнее
техническое имя, поэтому настройки и пакеты доступны после обновления.
При переходе с предыдущей версии сначала выберите «Выход» в её меню трея,
затем запустите новый EXE. Настройки сохранятся. Если автозапуск включён,
новая версия вместе с DLL установится отдельно, затем задача переключится на неё.
Настройки и скачанные пакеты остаются на прежнем месте.

Ручной выбор альта и адрес голосового сервера находятся на вкладке «Настройки».
Подробности проверок доступны на вкладке «Журнал»; текст можно выделять и копировать.
Оформление следует теме Windows, векторные элементы масштабируются средствами WPF.
Окно нельзя растягивать или разворачивать; содержимое прокручивается при необходимости.
История проверок раскрывается по нажатию. Масштаб DPI Windows сохраняется.
Fluent-ресурсы учитывают высокую
контрастность, индикатор — настройку анимаций. Доступность ещё нужно проверить на Windows.

## Что именно проверяется

- API: корректный ответ `GET https://discord.com/api/v10/gateway`.
- Gateway: WebSocket Hello с opcode 10 и корректным heartbeat interval.
- Голос: WebSocket Hello с opcode 8 от конкретного `*.discord.media:порт`.

Ответ HTTP с ошибкой, ping, DNS и просто открытый порт не засчитываются.
Используются новые соединения без системного HTTP-прокси. VPN на уровне сети
может влиять на результат: проверка оценивает текущее подключение компьютера.

**Адрес голосового сервера** автоматически определяется из недавних текстовых
журналов установленного Discord / PTB / Canary. Если в них ещё нет адреса,
приложение сначала подберёт временную стратегию для API/Gateway, затем попросит
открыть голосовой канал в Discord. Дальше всё проверяется автоматически, без
подтверждения слышимости. При необходимости адрес можно указать в поле вручную.
Без конкретного адреса проверка голоса не может завершиться успешно.

Из журналов извлекаются только имя/порт сервера и хеш строки для определения её
давности. Полные строки не сохраняются и никуда не отправляются. Пароли, токены,
данные учётной записи и браузерные хранилища приложение не читает.

Это **проверка ответа управляющего голосового сервера**, а не передачи UDP,
качества звука или всех регионов Discord. Формат журналов не является публичным
API Discord и может измениться. Если сервер устарел, повторно откройте голосовой
канал, чтобы Discord записал актуальный адрес. Кэш хранится до семи дней.

`ipset` в Flowseal — общий список IP-сетей, а не перечень голосовых серверов
с портами. Он применяется внутри стратегий и не используется как доказательство
работы голоса. Game Filter выключен по умолчанию; при его включении применяется
рабочий IPSet из репозитория, а не адрес-заглушка из релизного пакета.

## Telegram

На вкладке **Telegram** нажмите **«Запустить прокси»**, затем **«Открыть в Telegram»**
и подтвердите добавление прокси в Telegram Desktop на этом же компьютере.
Движок [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) 1.11.4
встроен в EXE «Связи» и работает в её процессе через CPython DLL. Нет отдельного
TgWsProxy.exe, python.exe, окна или значка в трее; устанавливать Python не нужно.
Если Telegram не открывается по ссылке, используйте «Скопировать ссылку».

Прокси слушает только `127.0.0.1`, по умолчанию порт 1443. В настройках вкладки
можно изменить порт и включить запуск вместе со «Связью». Перед сохранением
остановите прокси. Общий автозапуск Windows включается в настройках приложения.
Для новых установок Telegram выключен по умолчанию; прежнее значение сохраняется.

Telegram можно включить общей кнопкой через выбор сервисов в настройках или отдельно на его вкладке.
Статусы прокси и сервера показаны раздельно. Проверка отправляет анонимный MTProto
req_pq_multi через локальный прокси и ждёт resPQ с совпавшим nonce (до 12 секунд).
Она не входит в аккаунт и не подтверждает доставку сообщений, звонки или все дата-центры. После остановки выключите прокси в Telegram либо
снова запустите в «Связи». Закрытие окна оставляет «Связь» в трее; «Выход (остановить
всё)» останавливает оба подключения. Чужой TG WS Proxy не завершается автоматически.

Движок обновляется и откатывается вместе со «Связью». Отдельной загрузки EXE Flowseal
больше нет. Его исходники, Python и зависимости фиксируются версиями и SHA-256
в `telegram/runtime.lock.json`; сборка проверяет их до упаковки. При запуске DLL
проверяются перед загрузкой, пользовательский PYTHONPATH и site-packages не используются.
Поскольку движок теперь в одном процессе, нативный сбой может завершить всю «Связь».

Порт, ключ и автозапуск остаются в прежних настройках. Расширенные параметры один раз
переносятся из активного старого пакета (при его отсутствии — из подготовленного)
в `%ProgramFiles%\DiscordRoute\Data\Telegram\TgWsProxy_data\config.json`.
Старые пакеты и файлы сохраняются для отката. При необходимости расширенные параметры
можно изменить в этом JSON, пока прокси остановлен; отдельного редактора Flowseal нет.
Не публикуйте конфигурацию или ссылку подключения: они содержат ключ.
Журнал оригинального движка отключён, наружу передаются только классы ошибок.

Лицензия Flowseal MIT включена как `TG-WS-PROXY-LICENSE.txt`; лицензии Python и
зависимостей находятся внутри встроенного runtime и в его распакованной папке
`Data\Telegram\Embedded\<SHA-256>`.

## Game Filter

Откройте **Настройки → Игры · Game Filter**. Доступны четыре режима: выключен,
TCP и UDP, только TCP, только UDP. Исходный диапазон обоих протоколов —
`1024-65535`; в «Диапазонах портов» можно задать порты и интервалы через запятую,
например `1024-1934,1936-65535`. Допустимы порты 1–65535.

Сначала отключите обход на главном экране, выберите режим и нажмите
**«Сохранить Game Filter»**, затем подключитесь снова. Изменения не применяются
к уже работающему процессу. Настройки сохраняются для автозапуска и новых пакетов.

Как в Flowseal, фильтр расширяет обработку выбранных TCP/UDP-портов для сетей
из IPSet. Он не определяет игры по имени процесса. При включении используется
общий IPSet и для остальных ipset-правил стратегии; списки исключений сохраняются.
Работа конкретной игры проверяется в самой игре. Статус успешного подключения
в приложении по-прежнему относится к API, Gateway и голосовому серверу Discord.

При подключении приложение загружает список из официального источника:
https://raw.githubusercontent.com/Flowseal/zapret-discord-youtube/refs/heads/main/.service/ipset-service.txt

Кэш хранится в `%ProgramFiles%\DiscordRoute\Data\GameFilter\ipset-all.txt`.
На следующем подключении список старше шести часов обновляется; при ошибке
используется ранее проверенная копия. Если рабочей копии нет, подключение с
Game Filter не запускается с пустым списком или заглушкой. Можно выключить
Game Filter и подключиться обычным способом.

Загрузка ограничена по времени и размеру, принимаются только корректные IP-сети.
Для этого текстового списка используется HTTPS и проверка содержимого, а не
SHA-256 релизного ZIP. Загрузка BAT и запуск service.bat для переключения не нужны.

## Автозапуск и обновления

Автозапуск включается при первом запуске и управляется флажком в настройках. EXE
и пять DLL устанавливаются в `%ProgramFiles%\DiscordRoute\Versions\<хеш файлов>`.
Копия проверяется до переключения задачи; предыдущие версии сохраняются.
Самораспаковка нативных DLL в пользовательский временный каталог отключена. Планировщик Windows
создаёт задачу `DiscordRoute-<SID пользователя>` с повышенными правами, без пароля.
Через 15 секунд после входа этого пользователя приложение запускается в трее и
подключается. Если сеть ещё не готова, предусмотрено до пяти попыток подключения.
Кнопка отключения отменяет повторные попытки. Работа до входа пользователя
в систему этой версией не предусмотрена.

Проверка обновлений выполняется при запуске и каждые шесть часов, если включён
флажок. Обновляется полный **стабильный релиз** из
https://github.com/Flowseal/zapret-discord-youtube/releases/latest.
Стратегии из ветки main до выпуска релиза не подтягиваются отдельно.
Исключение — текстовый IPSet Game Filter: его штатный источник находится в main.
Автообновляются альты и файлы zapret; сама «Связь» получает обновления вместе со встроенным движком Telegram.

Перед распаковкой проверяется SHA-256, предоставленный GitHub для файла релиза.
Это проверка целостности относительно доверенного источника GitHub, не независимая
подпись автора. Пакеты без SHA-256, с опасными путями или несовместимым форматом
отклоняются. Загруженные BAT/PowerShell не исполняются: из general*.bat извлекаются
параметры для прямого запуска winws.exe. Неизвестные форматы пропускаются с записью
в журнал. Пользовательские списки `*-user.txt` переносятся в новый пакет.

При подключённом обходе новый пакет тестируется и становится активным только
после успеха; при неудаче проверяется предыдущий. Если оба не прошли, ранее
запущенный процесс восстанавливается с явным статусом «не проверен». При
отключённом обходе обновление ждёт следующего подключения. Отмена останавливает
управляемый процесс. Ошибка скачивания не удаляет имеющийся пакет.

Приложение не меняет hosts, DNS, брандмауэр, TCP timestamps или антивирус. Некоторые
стратегии upstream могут требовать настройки TCP timestamps; если они не работают
в текущей системе, подбор продолжится с другими стратегиями.

Данные: `%ProgramFiles%\DiscordRoute\Data` — настройки, пакеты и `app.log`.
В логах записываются результаты и диагностический вывод winws; ротация — 1 МБ.
После установки через Setup выйдите через трей и удалите «Связь» в параметрах Windows
→ Приложения. Удалятся приложение, ярлыки, скачанные версии и его задачи автозапуска.
Настройки, журналы и пакеты в `Data` сохраняются для переустановки.
Для полного удаления также удалите `Data`.
При использовании ZIP: выключите автозапуск, выйдите через трей, удалите папку
`%ProgramFiles%\DiscordRoute` и распакованный архив. Уже созданный драйвер WinDivert
управляется самим zapret; приложение не удаляет общие службы других установок.

## Обновление самой «Связи»

Начиная с **0.5.0** приложение автоматически проверяет стабильные релизы
`QeeDy777/svyaz` при запуске и каждые шесть часов, если включён флажок
**«Обновлять «Связь» и компоненты»**. Новая версия скачивается в фоне без остановки
соединений. Она применяется при следующем запуске с включённым автообновлением.
Для установки сразу откройте **Настройки → Обновление «Связи» → Обновить и перезапустить**.
Кнопка «Проверить новую версию» работает и при выключенном автообновлении; в этом
случае установка выполняется только по кнопке перезапуска.

Проверяются источник, стабильная версия, размер, SHA-256 GitHub, состав ZIP и версия
EXE. Вместе с EXE устанавливаются все пять WPF DLL. Установка выполняется в отдельный
каталог `%ProgramFiles%\DiscordRoute\Versions`, файлы работающей версии не заменяются.
Настройки, ключ Telegram, альты и списки остаются в прежней папке Data.
При явном перезапуске работавшие подключения Discord и Telegram запускаются снова;
это кратко прервёт связь. Выключенный автозапуск Windows остаётся выключенным.

Новая версия подтверждает создание окна; если она завершится раньше подтверждения
или не ответит за 30 секунд, приложение отклонит обновление и запустит прежний EXE.
Такой релиз больше не предлагается автоматически; ручная проверка позволяет
попробовать снова. Предыдущие версии сохраняются. После успешного обновления запуск
старой копии 0.5+ перенаправит на установленную новую версию.

**Переход с 0.4.0 и более ранних версий требует одного запуска нового установщика**:
там ещё нет кода автообновления. После этого скачивать ZIP вручную не нужно.
SHA-256 проверяет целостность относительно GitHub, а не подпись издателя.
Сертификата пока нет; SmartScreen и другие защиты Windows не отключаются.

## Сборка и проверки

Нужен .NET SDK 10 (C# 14). Сторонних NuGet-библиотек нет. Основное окно — WPF/XAML,
WinForms используется только для значка и меню в трее. Состояние и логика подключения
отделены от разметки.
Для `build.ps1` и подписи нужен PowerShell 7.4 или новее; для запуска готового EXE он не нужен.

```powershell
dotnet run --project tests/DiscordRoute.Checks
python scripts/prepare-telegram.py
dotnet publish src/DiscordRoute.App -c Release -r win-x64 --self-contained true -o dist/win-x64
```

`build.ps1` выполняет проверки, публикацию и создаёт ZIP с SHA-256.
По умолчанию выпускается `unsigned`. Инструкция по подписи — `SIGNING.md`
(в архиве — `SIGNING.txt`). Проверка логики подписи без сертификата:
`pwsh -File tests/Signing.Checks.ps1`. Тесты используют
локальный WebSocket-сервер на 127.0.0.1; ему требуется разрешение на локальные сокеты.
Windows-проверка окна WPF и встроенного DLL-движка: `dotnet run --project tests/DiscordRoute.WindowsChecks`.
Python-тесты: распакуйте `dist/telegram-runtime.zip`, укажите его каталог в `PYTHONPATH` и выполните `python tests/telegram_embed_checks.py` на Windows с Python 3.14. Проверяются повторный запуск, отмена, занятый порт и зашифрованный обмен через движок на локальном стенде.
Дополнительно можно передать путь к распакованному официальному релизу, его ZIP
и `--github-smoke` для проверки настоящего скачивания:

```powershell
dotnet run --project tests/DiscordRoute.Checks -- C:\Temp\zapret C:\Temp\zapret.zip --github-smoke
```

Проверки охватывают протокол, реальные локальные WebSocket-соединения, тайм-аут,
пакеты, парсер, все 22 стратегии официального релиза 1.10.4, отмену, откат,
сохранение пользовательских списков и XML автозапуска. Подробности: `VALIDATION.md`.

Сборка EXE не подписана сертификатом издателя; Windows может показать SmartScreen.
Создание окна, иконка и запуск/остановка настоящего Telegram-компонента проверены на Windows CI.
**Работа WinDivert, автозапуск при входе, сообщения и звонки ещё требуют проверки на вашем Windows-компьютере.**
Работа обхода зависит от сети; успешные автоматические проверки не гарантируют звук.

## Источники

Исходники страницы находятся в `site/`. Публикация на GitHub Pages выполняется
workflow `Publish website` при изменениях в ветке `main`.

- Telegram-компонент: https://github.com/Flowseal/tg-ws-proxy
- Flowseal: https://github.com/Flowseal/zapret-discord-youtube
- Протокол голоса: https://docs.discord.com/developers/topics/voice-connections
- Gateway: https://docs.discord.com/developers/events/gateway
- Планировщик: https://learn.microsoft.com/en-us/windows/win32/taskschd/logon-trigger-example--xml-

«Связь» — отдельная оболочка, не официальный продукт Discord или Flowseal.
Пакет zapret скачивается из upstream и распространяется на условиях его авторов.

## Установщик

Сборка на Windows: после `./build.ps1` выполните `./scripts/build-installer.ps1`
с [Inno Setup 6.7.3](https://jrsoftware.org/isdl.php). Можно передать `-IsccPath`.
Результат — Setup EXE и SHA-256 в `dist`. ZIP остаётся в релизе для автообновления
и запуска без установщика; его надо распаковывать целиком.

Установщик использует `%ProgramFiles%\DiscordRoute\Application` для стабильного
ярлыка. Проверенная копия добавляется в `Versions`, а указатель текущей версии
обновляется для старых ярлыков/задач. Более новая установленная версия не понижается.
Повторная установка сохраняет настройки и отключённый пользователем автозапуск.
При первом запуске новой установки автозапуск включается, как и раньше.
Setup содержит встроенный Telegram; пакет zapret загружается при первом запуске подключения.

Удаление останавливается, если приложение работает или не удалось удалить его задачи.
Задачи распознаются по имени `DiscordRoute-*` и единственному пути `Versions/…/Связь.exe`.
Чужие задачи не удаляются. Установщик и приложение пока не подписаны; возможен SmartScreen.


### Уведомление о готовом обновлении

После загрузки новой «Связи» над вкладками появляется плашка с кнопками
«Обновить и перезапустить» и «Позже». Первая использует обычную проверку файлов
и механизм перезапуска с возвратом к предыдущей версии при ошибке.
«Позже» скрывает плашку до следующего запуска; скачанные файлы остаются, кнопка
перезапуска в настройках доступна. Более новое скачанное обновление показывается снова.
Один и тот же пакет не вызывает повторных уведомлений при фоновых проверках.
Если окно скрыто в трее, показывается системное уведомление: нажатие открывает окно
с плашкой. Доставку системных уведомлений может ограничивать режим «Не беспокоить» Windows.

Полоса прокрутки отделена от содержимого постоянным зазором 14 DIP и собственной
областью шириной 16 DIP. Ползунок скруглён; прокрутка колесом, по дорожке и перетаскиванием
сохраняется. В журнале можно выделять и копировать текст.


### Удобство использования · 0.7.0

- **Исправить подключение** на экране Discord и в трее повторяет автоматический подбор,
  даже если в настройках выбран конкретный альт. Рабочая стратегия должна пройти
  две проверки API, Gateway и голосового сервера. Операцию можно отменить кнопкой питания.
- Вверху окна видны независимые статусы Discord и Telegram. На вкладке Discord — время
  текущего процесса и последняя успешная проверка, на вкладке Telegram — время прокси.
  Ответ голосового сервера не подтверждает передачу звука; работа локального прокси не подтверждает сообщения/звонки.
- Для каждой сети Windows запоминается успешно проверенный альт. При следующем подключении
  он проверяется первым. Смена сети требует повторного подключения; результат проверки,
  выполненной при смене сети, не сохраняется. При недоступном Windows Network List Manager
  используется обычный подбор. Хранятся хеши ID сетей, без SSID и IP.
- **Настройки → Сохранить отчёт** экспортирует JSON с версиями приложения/Windows,
  состоянием процессов, результатами проверок и HRESULT ошибок. В отчёт не попадают
  исходный журнал, адреса, пути, имена сетей, Telegram-секрет и настройки. Отправка только вручную.
- Меню трея показывает текущую стратегию и позволяет исправить подключение или проверить обновление «Связи».
- **Что нового · история версий** доступна офлайн в настройках и раскрывается при первом
  запуске новой версии. Ниже — сохранённые версии и кнопка возврата к последней более ранней.

Откат доступен для полных сохранённых копий начиная с 0.5.0; файлы и версия EXE
проверяются перед запуском. Он кратко прерывает подключения и выключает общий флажок
автообновления, чтобы прежняя версия не обновилась обратно. Возобновление обновлений —
через этот флажок или ручную проверку. Если старая версия не запускается, возвращается
текущая. Новые предпочтения лежат в `Data/preferences.json`, отдельно от старого
`settings.json`, поэтому откат не стирает сетевые профили. Установка нового Setup
считается явным обновлением и отменяет выбор старой версии.


### Проверка YouTube · 0.7.1

На вкладке «Подключение» показан отдельный результат **YouTube · HTTPS**. Альт
принимается только после двух успешных проходов всех проверок Discord и YouTube,
включая сохранённый альт для текущей сети. Если YouTube не проходит проверку,
подбор продолжается; при полном отказе действует прежний возврат процесса без
объявления соединения проверенным.

Для YouTube параллельно запрашиваются `https://www.youtube.com/generate_204` и
`https://redirector.googlevideo.com/generate_204`. Для каждого нужен HTTP 204.
Редиректы и HTTP 200 со страницей блокировки не принимаются. Проверка сертификатов
остаётся включённой; cookies и системный HTTP-прокси не используются. Тайм-аут
каждой точки — 7 секунд, отмена останавливает запросы.

Хосты взяты из [targets.txt Flowseal](https://github.com/Flowseal/zapret-discord-youtube/blob/main/utils/targets.txt).
Проверяется HTTPS сайта и перенаправителя Googlevideo, **не воспроизведение видео,
скорость, QUIC или доступность всех серверов видеопотока**. Результаты обеих точек
сохраняются в истории альта и журнале, а в диагностическом JSON — только как булевы
значения `YouTubeSitePassed` и `YouTubeGoogleVideoPassed`.


## Выбор сервисов и восстановление (0.9.0)

В настройках «Что подключать» выберите Discord, YouTube, Telegram и нажмите
«Сохранить выбор». По умолчанию выбраны Discord и YouTube; прежний автозапуск
Telegram сохраняется. Выбор меняется при отключённых соединениях. YouTube отдельно
не требует адреса голосового сервера. Для zapret обязательны два прохода всех
выбранных проверок; Telegram проверяется отдельно через встроенный прокси.

С версии 0.11.1 работающие подключения не проверяются в фоне, после сна или смены
сети. Работающий альт и Telegram-движок не перезапускаются автоматически.
При смене сети результат старой проверки сбрасывается; новый можно получить
при подключении или ручной проверке. Если сам процесс остановился, остаётся
восстановление с тремя попытками подключения. Кнопка «Отключить» отменяет повторы.
Обновления пакетов скачиваются автоматически, но применяются только при следующем
подключении. Автообновление самой «Связи» сохранено.

Сбой запуска или ручной проверки виден в окне; системное уведомление появляется после двух минут
проблемы и один раз до восстановления. Обычные успешные запуски не дают всплывашек.
Уведомления о сбоях отключаются в настройках. Уведомление о скачанном обновлении
приложения сохранено. Ошибки порта, отсутствующего голосового адреса и провала
проверок сопровождаются переходом к настройкам или кнопкой повторной проверки.

Протокол проверки Telegram: [req_pq_multi / resPQ](https://core.telegram.org/mtproto/auth_key), [MTProto transports](https://core.telegram.org/mtproto/mtproto-transports).


## Качество ответа (0.10.0)

Автоматический подбор сравнивает до трёх рабочих альтов, каждый должен пройти
три проверки выбранных сервисов. После первого рабочего проверяются ещё максимум
шесть стратегий. Оценка — медиана времени самого медленного ответа в каждом проходе
плюс разброс этих времён; меньше лучше. Поэтому чуть более медленный, но ровный
альт может выиграть у быстрого с резкими скачками. При равной оценке приоритет
остаётся у ранее сохранённого альта, если он участвует в сравнении.

Перед окончательным выбором стратегия запускается повторно и проходит ещё две
проверки. Если подтверждение не удалось, проверяется следующий сравнённый кандидат.
Ручной выбор оставляет только выбранный альт и прежние два прохода.

Главный экран и Telegram показывают до пяти последних замеров: медианный отклик,
разброс и число успешных проверок. У первого замера разброс не оценивается. Ошибки
учитываются в доле успеха, отключённые сервисы исключены. После смены сети,
стратегии или остановки выборка сбрасывается. Telegram измеряет время MTProto внутри
движка, без задержки опроса интерфейса. Фоновые измерения не переключают исправное
соединение ради меньшего времени ответа.

Это небольшая выборка сетевых проверок, включающая установление соединения и ответ
сервиса. Она не измеряет игровой ping, скорость скачивания, потери UDP или качество
звонка и не гарантирует результат за пределами проверенных кандидатов.

## Тихие фоновые проверки (0.10.1)

Историческое поведение 0.10.1–0.11.0; в 0.11.1 фоновые проверки сервисов удалены.

Периодические проверки Discord, YouTube и Telegram сохраняют последний результат
на экране до получения нового. Заголовок, подписи подключения и полоса прогресса
не переключаются в режим проверки. Отклик и время последнего успешного ответа
обновляются после результата. Ошибки и восстановление остаются видимыми.
Ручная проверка показывает прогресс; отключение прерывает и фоновую проверку.
Интервал остаётся прежним — примерно раз в минуту.

В 0.10.2 заголовок отражает запуск подключения, а не наличие последнего успешного
замера: «Связь включена» при работающем процессе и «Ожидаем подключения» при
ожидании восстановления без процесса. Отсутствие результата само по себе больше
не означает, что сейчас идёт проверка. Ответ каждого сервиса отображается отдельно.

## Полный подбор (0.11.0)

С версии 0.11.1 первое подключение без сохранённого рабочего альта автоматически
запускает полный подбор, включая подключение при автозапуске. После успешной проверки
и сохранения результата следующие подключения используют быстрый подбор.
Отмена, ошибка проверки или сохранения не завершают первоначальную настройку:
следующая попытка снова проверит весь список. У пользователей с уже сохранённым
альтом принудительного повторного подбора при обновлении нет. При переносе настроек
с другого ПК переносится и сохранённый результат; при удалении настроек подбор повторится.

Кнопка «Полный подбор» на вкладке «Подключение», ниже результатов сервисов,
проверяет все доступные стратегии пакета без ограничения в три рабочих кандидата
или шесть дополнительных попыток. Выбор в списке переключается на автоматический.
Проверяются выбранные Discord и/или YouTube; для режима только Telegram кнопка скрыта.

Рабочий кандидат должен пройти три полные проверки. Оценка прежняя: медианный
отклик плюс разброс. Лучший кандидат запускается заново и проходит две проверки;
при неудаче проверяется следующий по оценке. Подтверждённый результат сохраняется
для текущей сети, если сеть не изменилась. При неудаче нового пакета сохраняется
обычная возможность попробовать предыдущий пакет.

Во время подбора видны номер альта и общее количество. Неисправный кандидат
отсеивается при первой неудаче. Подбор занимает больше времени и переключает
winws, поэтому связь может прерываться. Основная кнопка отменяет подбор и отключает
соединение. Обычное подключение и фоновое восстановление остаются быстрыми.
