# Связь 0.9.0: удобное подключение

Пользователь подтвердил все пять предложений. Сохраняем фиксированное окно и существующие настройки; без новых зависимостей.

| Модуль | Результат | Зависимости |
| --- | --- | --- |
| service-selection | Общая кнопка запускает выбранные Discord, YouTube, Telegram | — |
| telegram-health | Проверка ответа MTProto через встроенный локальный прокси без аккаунта | — |
| recovery | Восстановление включённых подключений после сна/смены сети | service-selection, telegram-health |
| failure-help | Причина сбоя и подходящее действие, результаты проверок сохраняются | service-selection, telegram-health |
| quiet-alerts | Одно уведомление на длительный сбой, без сообщений об обычном старте | recovery, failure-help |

Порядок: выбор служб → проверка Telegram → восстановление/уведомления → интерфейс/Windows-проверки → выпуск.

## Условия приёмки
- По умолчанию Discord+YouTube, Telegram переносит прежний выбор автозапуска. Можно выбрать любую непустую комбинацию. Для YouTube отдельно голосовой адрес не требуется. Отключённые проверки не считаются пройденными.
- Общая кнопка запускает выбранные службы; отключение/отмена останавливает подключения и отменяет автоматические попытки. Отдельная кнопка Telegram сохраняется.
- Проверка Telegram передаёт анонимный req_pq_multi через локальный MTProto-прокси и принимает resPQ с совпавшим nonce. Тайм-аут, неверный ответ, отмена и остановка освобождают сокет. Статусы локального прокси и сервера раздельные; сообщения/звонки не утверждаем.
- События Windows Resume и смены сети запускают проверку с задержкой для стабилизации. Восстанавливаются только включённые пользователем службы, максимум три попытки с паузами. Отключение и выход отменяют ожидание. Повторные события объединяются; параллельные операции исключены.
- Уведомление только после двух минут неудач, один раз до восстановления/ручного отключения. Системные уведомления можно выключить. Обновление приложения сохраняет прежнее уведомление о готовом пакете.
- Ошибки сети, занятого порта, отсутствия голосового адреса и провала проверок объясняются в интерфейсе; рядом повторная проверка или переход к настройкам. Секреты не попадают в сообщения.

## Реализация и проверка
Core: настройки выбора, ограничения повторов и уведомлений, выбор проверок. App: MainViewModel, TelegramViewModel, MainWindow и DLL-host. Python: сетевой тест в существующем адаптере. Tests: существующие assert-проверки Core, Python loopback и Windows WPF/installer/updater.

Команды: `dotnet run --project tests/DiscordRoute.Checks`; `PYTHONPATH=/tmp/svyaz-tg-ws-proxy-upstream /tmp/svyaz-embed-tests/bin/python tests/telegram_embed_checks.py`; `python scripts/prepare-telegram.py`; `dotnet build tests/DiscordRoute.WindowsChecks`; Windows CI выполняет опубликованный EXE, установщик и откат.

Стиль: существующие короткие async-методы, отмена через CancellationToken, сериализация операций. Состояние UI изменяется на Dispatcher. Не меняем исходники Flowseal и не добавляем аккаунты/телеметрию. Сетевые ответы ограничены размером и временем. Обновление совместимо с прежним ZIP и preferences.json. Перед выпуском проверяем миграцию, выбранные комбинации, отмену, debounce, предел попыток, подавление уведомлений, MTProto nonce/тайм-аут и визуальное окно Windows.
