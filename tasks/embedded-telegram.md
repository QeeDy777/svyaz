# Встроенный Telegram-прокси

Пользователь подтвердил: полностью встроить движок, без отдельного процесса.

## Результат

«Связь» загружает CPython DLL и исходный сетевой движок Flowseal внутри своего процесса. Нет TgWsProxy.exe, python.exe, отдельного окна, трея или ручной установки Python. Текущие порт, ключ, автозапуск и дополнительные параметры сохраняются; чужой прокси не останавливается. Запуск остаётся на вкладке Telegram. Движок обновляется и откатывается вместе с «Связью».

## Решение и границы

- .NET 10, официальный CPython 3.14 x64, C API изолированной инициализации; без Python.NET и без переписывания MTProto.
- Зафиксированные исходники Flowseal 6690b788432fd0f59b0f38e228494bcd6bede1ca (1.11.4), только каталог proxy и лицензия. Python-зависимости фиксируются версиями и SHA-256.
- Ресурс ZIP внутри EXE сохраняет совместимость с allowlist автообновления старых версий. DLL извлекаются в защищённый каталог приложения и проверяются перед загрузкой.
- Импорт из рабочей папки, пользовательских каталогов и PYTHONPATH запрещён. Только loopback. Ключи не попадают в журнал/диагностику.
- Повторный старт/стоп, отмена, занятый порт и аварийное завершение обработаны. Сбой нативного движка теперь может затронуть приложение: проверяем реальный DLL-хост на Windows перед выпуском.
- Старые пакеты и конфигурации не удаляются: нужны для отката. Отдельное автоматическое скачивание EXE Flowseal больше не используется.

## Шаги и проверки

1. Зафиксировать сборку runtime, добавить адаптер жизненного цикла движка и тесты Python (включая обмен MTProto на локальном стенде).
2. Встроить DLL-хост и проверить запуск в процессе Windows, отсутствие дочерних процессов, остановку/повторный запуск/отмену.
3. Переключить TelegramViewModel; сохранить миграцию настроек, обновить тексты и документацию.
4. Проверить Core, WPF, автообновление из старого формата и откат, установщик; ревью и релиз.

Команды: `python3 scripts/prepare-telegram.py`; `python3 tests/telegram_embed_checks.py`; `dotnet run --project tests/DiscordRoute.Checks`; `pwsh ./build.ps1`; `dotnet run --project tests/DiscordRoute.WindowsChecks`; `pwsh ./tests/Installer.Checks.ps1`.

Новый код следует существующим коротким классам/async-методам. Внешние данные проверяются на границе. Изменения ограничены Telegram, упаковкой и необходимыми проверками. Реальную доставку сообщений в пользовательской сети без клиента Telegram не утверждаем.
