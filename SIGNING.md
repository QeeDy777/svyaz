# Подпись DiscordRoute и SmartScreen

Текущая поставка 0.6.0 **не подписана**: сертификат издателя и Microsoft Artifact
Signing не настроены. В имени архива указано `unsigned`. Скрипты ниже готовят
путь к подписанному релизу; они не оформляют сертификат и не обходят SmartScreen.

## Что даёт подпись

Authenticode подтверждает издателя и целостность EXE. SmartScreen дополнительно
оценивает репутацию файла и издателя: даже новая корректно подписанная программа
может показывать предупреждение. EV-сертификат тоже не гарантирует его отсутствия.
Самоподписанный сертификат не создаёт публичного доверия.

Запрос прав администратора UAC остаётся отдельным механизмом: WinDivert и
установка автозапуска требуют повышения прав. Не отключайте Defender/SmartScreen
для распространения программы. Скрипты не удаляют метки загрузки и не меняют защиту.

## Вариант 1: сертификат доверенного центра

1. Оформите сертификат Code Signing на своё имя/организацию у доверенного центра.
   Проверьте доступность в вашей стране и требования проверки личности до оплаты.
   Обычно ключ хранится на аппаратном токене или у облачного провайдера.
2. На Windows установите PowerShell 7.4+, Windows SDK с SignTool и ПО провайдера ключа.
   Сертификат должен быть доступен в `CurrentUser\My` текущему пользователю,
   а приватный ключ — через провайдера. Пароли и ключи не добавляйте в репозиторий.
3. Найдите свой сертификат (не используйте автоматически первый попавшийся):

   ```powershell
   Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert |
       Select-Object Subject, Thumbprint, NotAfter, HasPrivateKey
   ```

4. Запустите сборку из PowerShell, подставив **свои** значения. URL timestamp
   должен поддерживать RFC 3161; возьмите его из инструкции вашего центра.

   ```powershell
   .\build.ps1 `
       -CertificateThumbprint '40_HEX_CHARACTERS_OF_YOUR_CERTIFICATE' `
       -SignToolPath 'C:\Program Files (x86)\Windows Kits\10\bin\YOUR_SDK_VERSION\x64\signtool.exe' `
       -TimestampUrl 'https://YOUR_CA_RFC3161_ENDPOINT'
   ```

   Пример содержит шаблоны, а не рабочие реквизиты. Скрипт использует SHA-256 для
   подписи и timestamp. `/sha1` обозначает способ выбора сертификата по отпечатку,
   а не алгоритм подписи файла. SignTool проверяет подпись с `/pa /all /v /tw`;
   дополнительно проверяются издатель и наличие timestamp через Authenticode.
   Ошибка на любом шаге прерывает выпуск. PIN запрашивает провайдер ключа.

5. Результат: `dist/Svyaz-0.5.0-win-x64-signed.zip` и соседний `.sha256`.
   Подпись выполняется **до** создания ZIP и контрольной суммы. Повторный
   `dotnet publish` создаёт новый неподписанный EXE — его необходимо подписать заново.

Без параметров `./build.ps1` выпускает только `…-unsigned.zip`. Для уже собранного
каталога можно вызвать `scripts/sign-release.ps1` с теми же параметрами и
`-PublishDirectory`, затем самостоятельно упаковать и пересчитать SHA-256.
Не выдавайте старый архив или старую контрольную сумму за подписанный релиз.

## Вариант 2: Microsoft Artifact Signing

Artifact Signing (прежнее название Trusted Signing) хранит ключи у Microsoft.
Нужны Azure, доступность услуги для вашего региона/типа заявителя, проверка
личности, signing account и профиль Public Trust. Это не настроено в проекте.

После оформления используйте официальный клиент/CI-интеграцию Artifact Signing
для подписи опубликованного `Связь.exe`, проверяйте его через SignTool и
только затем создавайте архив и SHA-256. Скрипт `sign-release.ps1` предназначен
для сертификата из хранилища Windows, а не для профиля Azure.

## Перед распространением

Проверьте подписанный EXE на Windows: «Свойства → Цифровые подписи», доверенного
издателя, timestamp, запуск интерфейса, подключение и автозапуск. Подпись оболочки
не распространяется на скачанный пакет Flowseal: его целостность приложение
проверяет по SHA-256 GitHub. Не переподписывайте чужой драйвер своим сертификатом.

Microsoft Store имеет отдельные правила распространения и сертификации.
Совместимость этого приложения с Store не проверена и не заявляется.

## Установщик 0.6

`scripts/build-installer.ps1` создаёт `setup-unsigned.exe` и отдельную SHA-256 сумму.
Подпись EXE внутри ZIP не подписывает внешний установщик. Для подписанного выпуска
нужно также настроить [SignTool в Inno Setup](https://jrsoftware.org/ishelp/topic_setup_signtool.htm),
включить `SignedUninstaller=yes` и проверить подписи внешнего Setup и встроенного
деинсталлятора. Только после проверки подписи и timestamp пересчитайте SHA-256.
Текущий скрипт намеренно не называет такой файл `signed` автоматически.
